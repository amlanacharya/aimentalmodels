Cloud, Containers & AI Deployment

Docker, Kubernetes, GPU scheduling, autoscaling, configuration, secrets, rollout strategies and when persistent infrastructure beats serverless.

01 · Containers

Package the runtime before orchestrating it

Containers give you a reproducible unit containing the application and its dependencies.

Code→Image→Container→Deployment
Mental model: Docker solves packaging. Kubernetes solves scheduling and lifecycle across a fleet.
02 · Kubernetes

Think desired state, not SSH into servers

Kubernetes continually reconciles the running system toward the declared state.

03 · GPU scheduling

A GPU is a schedulable scarce resource

GPU clusters add drivers, device plugins, runtime integration, topology and utilization concerns.

Node→GPU driver→Device plugin→Pod requests GPU

GPU Operator

In Kubernetes environments, operators can automate the driver, device-plugin, container-toolkit, node-labeling and monitoring stack instead of managing each component manually.

04 · Autoscaling

Scale on the bottleneck that predicts pain

CPU percentage is often a poor signal for AI serving.

WorkloadUseful signals
LLM servingQueue depth, concurrent sequences, KV pressure, tokens/sec, TTFT
API tierRequest rate, latency, event-loop saturation
WorkersQueue age, backlog, processing time
GPU poolUtilization, memory, pending workloads, topology
05 · Config & secrets

Images should be immutable; environments should vary by configuration

Do not bake API keys, tenant settings or production endpoints into images.

Configuration

Model route, feature flags, limits, endpoints, runtime modes.

Secrets

Credentials, signing keys, database passwords, provider tokens.

06 · CI/CD & rollout

Deploy AI changes as experiments with rollback

Prompt, model, retriever and backend changes can all regress quality.

Build→Tests + evals→Shadow→Canary→Ramp→Rollback if needed
07 · Serverless vs persistent

Choose by workload shape

Short bursty orchestration is different from keeping a 70B model warm.

Serverless / scale-to-zero

Good for bursty APIs, webhooks, preprocessing and asynchronous control-plane work.

Persistent workers

Better when startup cost is high, GPU weights must remain loaded, or long-lived queues need predictable capacity.

What to remember

Cloud & deployment 80/20

Deployment is the bridge from a correct artifact to a reproducible, scalable, recoverable service.

Containerize reproducibly
Keep config outside images
Keep secrets out of source
Use workload-aware scaling signals
Treat GPUs as scarce scheduled resources
Use health checks and graceful shutdown
Run eval gates in CI/CD
Canary risky changes
Design rollback before launch
Do not default to Kubernetes for tiny systems
