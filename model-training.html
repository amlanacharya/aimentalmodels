The whole subject in one loop

Training is repeated error correction

A neural network starts with parameters. A batch goes through the model, the loss says how wrong the output was, backpropagation assigns blame to parameters, and the optimizer moves them.

Batch→Forward pass→Loss→Backprop→Optimizer step→Repeat
θ ← θ − learning_rate × gradient
Mental model: nearly every training technique modifies one of four things: the data, the objective, the gradients, or how the optimizer applies those gradients.
Backpropagation

The model learns by assigning blame backward

Backpropagation uses the chain rule to answer a practical question: if this parameter changed slightly, how would the loss change?

Forward computes activations. Backward computes how sensitive the loss is to each parameter.

Gradient

A direction and magnitude telling the optimizer how the loss changes with a parameter.

Automatic differentiation

Frameworks such as PyTorch record operations and compute gradients for you; your job is to reason about whether those gradients are useful and stable.

Learning rate

The most important training knob is step size

Too small and training crawls. Too large and the optimizer jumps across useful regions or diverges. The right scale often matters more than swapping optimizers.

Steadyconvergence speed
Lowinstability risk
Useful descentlikely behavior
Illustrative intuition only, not a recommendation for a literal optimizer learning rate.

Warmup

Start with smaller steps while activations and optimizer statistics stabilize.

Decay

Reduce the learning rate later so updates become finer as training converges.

Schedule

Cosine and linear schedules are common ways to change step size across training.

Batch, epoch & accumulation

Three terms explain most training-loop configuration

TermMeaningWhy you care
BatchExamples used to estimate one gradient updateAffects memory, gradient noise, and throughput
EpochOne pass through the training datasetUseful bookkeeping for finite datasets
Gradient accumulationAccumulate gradients over several micro-batches before steppingSimulates a larger effective batch when memory is limited
effective batch = micro_batch × accumulation_steps × data_parallel_workers
Do not equate “bigger batch” with “better.” Bigger batches usually improve hardware utilization and reduce gradient noise, but can require learning-rate retuning and may change generalization.
Optimizers

SGD gives the intuition; AdamW dominates practical transformer training

SGD

θ ← θ − ηg

Move parameters opposite the gradient. Momentum adds memory of previous directions so noisy updates become smoother.

Adam / AdamW

Track moving averages of gradients and squared gradients, giving parameters adaptive step sizes. AdamW decouples weight decay from the momentum/variance update.

TransformersFine-tuningLarge-scale training
Mental model: AdamW rescales and smooths gradients using running statistics, then applies decoupled weight decay.
Gradient stability

Vanishing and exploding gradients are signal problems

Vanishing

Gradients become tiny as they travel through many operations. Early layers barely learn.

gradient ≈ 0 → parameter barely moves

Exploding

Gradients become huge, creating unstable updates, NaNs, or divergence.

|gradient| ≫ normal → destructive update
Residual connections+Normalization+Good initialization+Gradient clipping
Gradient clipping limits extreme gradient norms; it is a guardrail, not a cure for fundamentally broken optimization.
Normalization

Keep activations in a trainable numerical regime

Transformers rely heavily on normalization around residual blocks because depth compounds instability.

LayerNorm

Normalizes features within each token/example. Historically common in transformers.

RMSNorm

Normalizes by root-mean-square magnitude without subtracting the mean; common in many modern LLM architectures.

Training intuition: normalization does not “make data normal.” It controls scale so optimization remains numerically manageable.
Mixed precision

Use fewer bits where you can, more precision where you must

Training in FP32 everywhere wastes memory and compute. Modern accelerators are designed around lower-precision formats such as FP16, BF16, and increasingly FP8, while sensitive operations may remain higher precision.

Lower precision matmuls→Less memory→Higher throughput

BF16

Large exponent range makes it generally easier to train with than FP16 on supported hardware.

FP16 + loss scaling

Very small gradients can underflow; gradient scaling shifts them into a representable range and skips unsafe updates when overflow is detected.

Training memory

Weights are only part of the bill

Inference mostly needs weights plus runtime state. Training additionally stores gradients, optimizer states, and forward activations needed for backpropagation.

14 GBFP16/BF16 weights
~112 GBillustrative params + grads + Adam states*
Variableactivations scale with batch/sequence/depth
*Simplified teaching estimate. Real frameworks differ by precision, master weights, optimizer implementation, sharding, and recomputation.

Activation checkpointing

Store fewer intermediate activations and recompute them during backward. Trades extra compute for lower memory.

Sharding

Split parameters, gradients, and/or optimizer states across workers so each GPU stores only a fraction.

Distributed training

Choose parallelism based on what no longer fits

StrategySplitUse when
Data parallelBatch across model replicasModel fits on each GPU; you need more throughput
FSDP / ZeRO-style shardingParameters, gradients, optimizer stateModel state is the memory bottleneck
Tensor parallelIndividual large layers/tensorsA layer is too large for one device
Pipeline parallelLayers by depthVery deep models need to span devices
Context / sequence parallelSequence dimensionLong contexts make activations expensive
Expert parallelMoE expertsMixture-of-experts architectures
Start simple: data parallel first. Add sharding when model state does not fit, tensor parallel when individual layers do not fit, pipeline parallel when depth must span devices, and context parallel when sequence length dominates activation memory.
Checkpoints & failure recovery

A checkpoint is more than weights

Resume training

For a faithful resume you may need model parameters, optimizer states, scheduler state, gradient-scaler state, RNG state, and dataloader progress.

Model artifact

For deployment you often export only the trained model weights/config/tokenizer, not the full training state.

Operational lesson: distributed training without checkpoint/restart strategy is a very expensive way to discover hardware failures.
What to remember

The training 80/20

Forward pass produces predictions
Loss defines what “better” means
Backprop computes parameter sensitivities
Optimizer applies gradient-informed updates
Learning rate controls update size
Batch size changes memory, throughput, and gradient noise
AdamW uses adaptive moments plus decoupled weight decay
Warmup and decay stabilize optimization
Residuals and normalization make deep networks trainable
Mixed precision saves memory and compute
Training stores far more than weights
Activation checkpointing trades compute for memory
Data parallel scales batches
FSDP/ZeRO shard model state
Tensor/pipeline/context parallel solve different fit problems
Checkpoint training state, not only model weights

If you understand one sentence

Training repeatedly measures error, computes how each parameter contributed to that error, and applies controlled updates, while most large-scale engineering exists to keep those updates numerically stable and memory-feasible.
