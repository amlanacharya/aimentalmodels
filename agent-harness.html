Agent Architecture & Harness Engineering

The model is only the brain. The harness controls context, tools, state, recovery, permissions, and termination. Learn the small set of patterns that explain most production agents.

Core mental model

The harness is the control system around the model

An agent is not just an LLM with tools. The harness decides what the model sees, what it can do, how state persists, when it retries, and when execution stops.

The model can improve without rewriting the whole system if the surrounding interfaces remain stable.
Mental model: model quality matters, but harness quality determines whether that intelligence becomes reliable work.
Agent loop

ReAct: reason, act, observe, repeat

ReAct interleaves reasoning with actions against an environment. The useful engineering abstraction is a loop where every action produces an observation that changes the next decision.

Goal→Reason→Act / tool→Observe↺

Why it works

External actions can correct stale internal assumptions. Search, code execution, APIs, and databases turn reasoning into grounded interaction.

What production adds

Typed tool calls, limits, retries, timeouts, state persistence, stop conditions, and approvals. ReAct alone is not a reliability layer.

Think loop, not monologue: the agent should get new evidence before making the next consequential decision.
Architecture patterns

Workflow before agent

If you already know the path, encode the path. Use model autonomy where the next step genuinely cannot be predetermined.

Control flow

Routers decide where work goes; state machines decide what transitions are legal

Router

request → classify intent → route to capability

Useful for selecting a tool, specialist prompt, retriever, model, or sub-agent.

State machine

DRAFT → REVIEW → APPROVED → EXECUTED

Useful when business rules constrain what can happen next.

Strong pattern: let the model propose a transition; let deterministic code decide whether that transition is legal.
Capability design

Skills tell the model how to work; tools let it change the world

Instruction

Always-on behavior such as tone, safety policy, output contract.

Skill

Situational procedure: when a task matches X, follow this playbook, vocabulary, and decision process.

Tool

An executable capability with inputs, outputs, permissions, and possible side effects.

skill = procedural knowledge tool = executable capability

Do not create a tool when the model only needs instructions. Do not bury a real external action inside prose when it should be a typed tool.

Context engineering

The context window is working memory, not a data warehouse

Agent quality often depends more on what enters the context than on adding another orchestration layer.

Put in context

Current goal, relevant state, tool contracts, compact evidence, recent observations, active constraints.

Keep out

Irrelevant history, giant tool catalogs, duplicated documents, stale plans, verbose traces that no longer affect the decision.

Full history→Select→Compress→Current working context
Context engineering = attention allocation. Every unnecessary token competes with information you actually need the model to use.
Persistence

Separate working context, workflow state, memory, and checkpoints

ThingQuestion it answersLifetime
Working contextWhat does the model need right now?Current call / short horizon
Workflow stateWhere are we in this task?Task lifetime
MemoryWhat should future runs remember?Across tasks/sessions
CheckpointFrom what exact state can execution resume?Durable recovery point
Checkpointing changes reliability: after failure or human review, resume from a known state instead of replaying the whole trajectory.
Human control

Human-in-the-loop is a boundary, not a fallback apology

Put approval where uncertainty meets high consequence.

Approve

Agent proposes an action; human authorizes execution.

Edit

Human modifies arguments or state, then execution resumes.

Escalate

Agent stops because confidence, policy, or risk threshold was exceeded.

low risk → autonomous medium risk → verify high / irreversible risk → approve
Long-horizon reliability

Why long autonomous loops fail

Every extra step creates another opportunity for a wrong assumption, stale context, bad tool output, or unrecoverable side effect.

Error compounding

If each step has probability p of being correct, a simplified all-steps-success model behaves like p^n.

0.95^20 ≈ 0.36

Context degradation

Long traces accumulate irrelevant observations and outdated plans. The model may optimize against its own previous mistakes.

Mitigate

Replan after material observations.

Mitigate

Checkpoint completed work and make tools idempotent.

Mitigate

Use explicit budgets: max steps, max cost, max retries, max wall time.

Putting it together

A production agent harness blueprint

A harness turns an open-ended model loop into a bounded, observable, resumable execution system.
Explicit stop criteria
Typed tool contracts
Bounded retries and budgets
Durable checkpoints
Context pruning / compression
Approval at consequential actions
Trace every decision boundary
Evaluate trajectories, not just answers
