Module 06 · Search & retrieval

Embeddings, Vector Search & Retrieval Internals

RAG starts before the LLM sees a single retrieved token. Learn what an embedding represents, how nearest-neighbour search is made fast, and why production retrieval usually needs more than “cosine similarity + top-k”.

On this page1. Retrieval pipeline2. Embedding geometry3. Cosine, dot product, L24. Exact vs ANN5. HNSW6. IVF & PQ7. Dense + lexical8. Reranking9. Chunking10. Failure modes
01 · Start with the system

Retrieval is a funnel, not one similarity calculation.

A production retriever narrows a huge corpus into a tiny context set. Different stages trade recall, precision, latency, and cost.

query→query embedding→candidate retrieval→filters / hybrid fusion→reranker→top context

The Pareto mental model

First stage: search broadly and cheaply. Second stage: spend more compute on a small candidate set. This architecture appears repeatedly across search and RAG.

02 · Geometry of meaning

An embedding is a coordinate, not a fact.

An embedding model maps an input into a fixed-length vector. Similar meaning should land in useful geometric relationships, but the vector itself is only meaningful relative to the model and similarity function used.

Text → vector

"refund policy" → [0.14, -0.72, 0.31, …]

You rarely interpret dimensions individually. What matters is where vectors sit relative to one another.

Search

query vector → compare → rank corpus vectors

Nearest-neighbour retrieval asks which stored vectors are closest under the chosen metric.

Illustrative 2-D projection. Real embeddings may have hundreds or thousands of dimensions.
03 · Similarity metrics

Cosine asks about direction. Dot product also feels magnitude.

Cosine similarity

cos(a,b) = (a·b) / (||a|| ||b||)

Compares angle after accounting for vector length.

Dot product

a · b = Σ aᵢbᵢ

Higher when vectors align, but magnitude can influence the score.

L2 distance

||a - b||₂

Measures geometric distance between coordinates.

35°angle
0.819cosine similarity
strong alignmentintuition
Practical shortcut: with L2-normalized vectors, cosine ranking can be implemented as maximum inner product search; Faiss documents this equivalence explicitly.
04 · Scale changes the algorithm

Exact nearest neighbours are simple. Approximate search is what makes large corpora practical.

Exact / flat search

Compare the query against every stored vector.

work ≈ N × vector_dimension

Excellent ground truth. Expensive as N grows.

Approximate NN (ANN)

Use an index to avoid evaluating every vector.

less search work ↔ possible recall loss

The core systems trade-off is speed/memory versus nearest-neighbour recall.

45%relative search effort
86%illustrative NN recall
moderaterelative latency

Conceptual only: real curves depend on index, corpus, hardware and tuning.

05 · Graph-based ANN

HNSW navigates a graph instead of scanning the entire corpus.

Think of each vector as a node linked to nearby nodes. Upper layers contain long-range shortcuts; lower layers provide increasingly local navigation.

Tuning intuition

Search more neighbours → usually better recall → more latency. Build denser graphs → more memory/index cost.

Why people like it

Strong recall/latency behavior and no need to probe every vector. Trade-off: graph memory can be substantial.

06 · Partition + compress

IVF narrows the region. PQ shrinks the vectors.

IVF (inverted file)

Cluster vectors around centroids. At query time, search the nearest few clusters rather than all vectors.

query→nearest centroids→probe selected lists

PQ (product quantization)

Split vectors into subvectors and encode each piece using a small codebook. Search operates on compact approximations.

768-D vector→subvectors→compact codes
When to think IVF/PQ: when corpus scale and memory footprint matter enough that you accept additional approximation and index tuning.
07 · Semantic is not enough

Dense retrieval understands meaning. Lexical retrieval protects exact terms.

Product codes, names, error IDs and rare phrases can be poorly served by semantic similarity alone. Hybrid search combines lexical and vector rankings.

Dense / semantic

Good for paraphrases and conceptual similarity.

"cancel my subscription" ≈ "end my plan"

Lexical / BM25-style

Good when exact tokens matter.

ERR-7421 should match ERR-7421
dense rankinglexical ranking→RRF / weighted fusion→merged candidates
RRF intuition: combine ranks rather than forcing incomparable raw scores onto one scale. Documents ranking highly in either list receive useful credit.
08 · Two-stage retrieval

Retrieve cheap. Rerank expensive.

Embedding search gives you candidates quickly. A reranker then examines the query and each candidate more deeply and reorders the shortlist.

1,000,000 chunksANN →top 50reranker →top 8→LLM context

Bi-encoder retrieval

Query and documents are embedded independently, so document vectors can be precomputed. Fast enough for broad retrieval.

Cross-encoder reranking

Query and candidate are considered together. More expensive, but usually provides a richer relevance judgment.

Core architecture: first stage optimizes candidate recall. Reranking optimizes ordering and precision in the final context window.
09 · Your index unit matters

Chunking determines what the retriever is allowed to find.

Too small

High granularity but weak context. The answer may span multiple chunks.

Too large

More context per hit, but embeddings blur multiple topics and waste downstream tokens.

Structure-aware

Respect paragraphs, sections, tables, headings and parent-child relationships when document structure carries meaning.

A stronger default than “pick 500 tokens”

start with document structure
measure retrieval recall on real queries
preserve metadata and parent IDs
retrieve children, expand parents when useful
test overlap rather than assuming it helps
separate chunking eval from generation eval
10 · Diagnose retrieval

A high similarity score can still retrieve the wrong evidence.

FailureWhat happenedTypical fix
Semantic collisionText is conceptually similar but answers a different question.Rerank; add metadata constraints.
Exact-term missDense search loses an identifier, SKU, name or code.Hybrid lexical + dense retrieval.
Chunk boundaryEvidence is split across chunks.Structure-aware chunking, overlap, parent expansion.
ANN missThe approximate index never surfaced the true neighbour.Increase search effort / probes / efSearch; benchmark recall.
Filter errorCorrect vector exists but tenant/time/access filters exclude it, or fail to exclude unsafe data.Treat metadata and ACL logic as retrieval correctness.
Embedding mismatchModel geometry does not represent the domain/query type well.Benchmark another embedding model or task-specific retriever.

The retrieval debugging ladder

Is evidence indexed?→Can exact search find it?→Can ANN surface it?→Does reranking keep it?→Does context construction preserve it?
