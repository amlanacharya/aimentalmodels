Transformer internals: attention, memory, and token flow

This is the bridge from “the model outputs probabilities” to “what actually happens inside the model before those logits exist.” You only need a handful of mechanisms to understand most modern decoder-only LLMs.

The whole transformer in one line

Represent tokens → let tokens read relevant earlier tokens → mix features through an MLP → repeat many times → project the final representation into vocabulary logits.

1. A transformer block

A modern decoder LLM is mostly the same block repeated many times. Exact ordering differs by architecture, but the mental model is stable.

Pareto cut: attention moves information between tokens; the MLP transforms information inside each token representation; residual connections keep earlier information available.

2. Q, K, V attention

Each token produces three learned views of itself. The names are easier than the notation suggests.

VectorMental model
Query (Q)What information am I looking for?
Key (K)What kind of information do I contain?
Value (V)What information should I contribute if selected?
Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V
Pareto cut: Q and K decide where to read. V contains what gets read. The softmax turns similarity scores into weights.

3. Causal self-attention

A decoder-only LLM must not look at future tokens while predicting the next token. A causal mask blocks those attention links.

Pareto cut: “self-attention” means tokens attend within the same sequence. “causal” means a token can only use itself and earlier positions.

4. Positional information & RoPE

Attention by itself has no natural sense of word order. Modern LLMs inject position information so “dog bites man” is not treated like “man bites dog.”

token content+position signal→order-aware attention

RoPE (rotary positional embeddings) encodes relative position by rotating query/key features as position changes. You do not need the trigonometry to use the idea.

Pareto cut: positional encoding tells attention where tokens are. RoPE is especially useful because position relationships become part of Q/K comparisons.

5. MHA vs GQA vs MQA: the KV-cache connection

The attention variants differ mainly in how many Key/Value heads are stored and shared. That matters enormously during inference because K and V are what the cache keeps for every previous token and every layer.

VariantQuery headsKV headsPractical intuition
MHAmanymanymaximum per-head flexibility, largest KV cache
GQAmanya few groupsstrong middle ground: less cache, retains multiple KV groups
MQAmany1smallest KV cache, all query heads share one K/V set

6. Prefill vs decode

LLM inference has two different phases that behave differently on hardware.

PhaseWhat happensWhat you feel
Prefillprocess the prompt tokens and build K/V statestime to first token
Decodegenerate one new token at a time while reusing cached K/Vtokens per second
prompt: N tokens→PREFILL→KV cache→DECODE 1 token↻
Pareto cut: prompt processing and token generation are different workloads. That is why TTFT and decode tok/s should be measured separately.

7. KV cache

Without caching, autoregressive decoding would repeatedly recompute the same K/V representations for old tokens. The KV cache stores those tensors once and reuses them.

Pareto cut: context length consumes inference memory because the cache grows with stored token states. MQA/GQA, cache quantization, sliding windows, and cache offloading all attack this bottleneck from different angles.
Illustrative decoder: 32 layers, head dimension 128, FP16/BF16-style 2-byte cache elements. Formula ignores implementation overhead and model-specific optimizations.

The chain to remember

tokens→embeddings + position→Q/K/V attention→MLP→ × layers →logits→softmax + sampling

During generation, the prompt goes through prefill, K/V states are stored, and decode produces one new token at a time while reusing that cache.
