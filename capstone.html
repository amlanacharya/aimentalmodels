01 · Capstone brief

Build an enterprise research-and-action copilot

The capstone combines every module into one system: private knowledge retrieval, multimodal documents, tool actions, approvals, durable jobs and production operations.

Scenario

Employees ask questions across policies, PDFs, structured operational data and meeting notes. The copilot can answer with citations, run approved tools, draft actions, and execute high-risk actions only after human approval.

Multi-tenantRAGAgentsMultimodalHITLAudit
02 · End-to-end architecture

Put every concept on one request path

This is the final mental model for the course.

The capstone architecture intentionally exposes model, retrieval, tools, state, security, eval and operations as separate concerns.
03 · Data plane

Build the knowledge supply chain

Raw documents must become permission-aware, versioned retrieval units.

Sources→Parse/OCR/Vision→Canonical doc→Chunk + metadata→Index
Acceptance: every retrieved chunk can be traced to source, version, permissions and parser/index version.
04 · Runtime plane

Use deterministic control around probabilistic decisions

The model may select an action; the harness validates whether it is allowed and safe to execute.

model proposal → schema validation → authorization → policy → execute → verify → persist → audit

Low-risk

Read/search/draft may execute automatically.

High-risk

Payments, deletes, external sends or privilege changes require stronger policy and often human approval.

05 · Evaluation

Evaluate each stage and the final task

A single end-to-end score cannot diagnose the system.

LayerExample metrics
RetrievalRecall@k, NDCG, permission leakage = 0
GenerationCorrectness, faithfulness, citation accuracy
ToolsArgument validity, execution success, side-effect correctness
AgentTask success, steps, cost, unsafe-action rate
Productionp95 latency, availability, escalation, cost/success
06 · Security

Threat-model retrieved content and tools as untrusted

The capstone is not complete until prompt injection and authorization are tested.

Tenant filters enforced outside prompts
Indirect prompt-injection test corpus
Typed tool schemas
Least-privilege credentials
Sandbox untrusted code/content
Approval gates for high-risk actions
PII handling policy
Audit every consequential action
07 · Production

Ship with SLOs, canaries and rollback

The capstone must be operable, not merely demoable.

Offline eval→Shadow→Canary→Ramp→Monitor
trace_id links API → retrieval → model → tool → state → cost → outcome
08 · Capstone deliverables

What you should actually produce

A serious capstone is a system package, not a screenshot.

Architecture pack

Context diagram, request flow, data flow, trust boundaries, storage choices, deployment diagram.

Evaluation pack

Golden set, retrieval evals, tool tests, agent trajectories, regression thresholds.

Operations pack

SLOs, dashboards, alerts, rollout plan, runbook, rollback procedure.

Decision log

Why this model, retrieval strategy, state store, serving stack and security boundary were chosen.

09 · Mastery test

You are done when you can explain the trade-offs

The goal of the entire site is not memorization. It is being able to reason from first principles.

Explain what happens from tokenization to decode
Diagnose retrieval vs generation failure
Choose prompt vs RAG vs fine-tuning
Estimate training/inference memory
Explain GPU/network bottlenecks
Design a safe agent harness
Build stage-specific evals
Design backend flow control
Choose storage by semantics
Deploy with canary and rollback
Capacity-plan and price the system
Threat-model and audit the system

The final mental model

Production AI engineering is the discipline of placing probabilistic models inside deterministic systems that can retrieve evidence, execute controlled actions, measure quality, recover from failure, and operate economically at scale.
