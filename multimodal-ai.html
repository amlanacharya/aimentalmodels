Module 11 · Multimodal AI

How models see, hear, and reason across modalities.

The master mental model

Every modality must become something the model can attend to

Text already arrives as tokens. Images, audio, and video first need an encoder that converts raw signal into vectors. A connector then maps those vectors into a representation the language model can consume.

The exact architecture varies, but the recurring pattern is encode → align/project → attend/reason.
Remember: multimodal models do not “look at pixels like humans.” They operate on learned representations of those pixels.
Vision

Vision encoders turn pixels into patch-level representations

A common approach is to split an image into patches, embed each patch, then run a vision transformer or similar encoder over those patch embeddings.

Image→Patches→Patch embeddings→Vision encoder→Visual features

What the encoder learns

Shapes, textures, objects, layout, spatial relationships, and higher-level semantics.

What matters to engineers

Image resolution, number of visual tokens, encoder size, and how aggressively features are compressed before they reach the LLM.

Joint embedding spaces

CLIP-style training makes text and images comparable

The core idea is contrastive learning: bring matching image-text pairs closer in embedding space and push mismatched pairs apart.

similar(image_embedding, text_embedding) ↑ for matching pairs
Illustrative geometry: semantically matching image and text representations cluster together.
Why this matters: once modalities share a comparable space, cross-modal search becomes simple nearest-neighbor retrieval.
Vision-language models

Image features become visual tokens the LLM can attend to

Systems such as LLaVA connect a vision encoder to a language model through a learned projection layer. The LLM receives visual features alongside text context and generates text conditioned on both.

Vision encoder→Visual features→Projection→LLM token space

More visual tokens

Usually preserve more detail, but consume more context and compute.

Fewer visual tokens

Cheaper and faster, but may lose small text or fine spatial information.

Reasoning layer

The LLM integrates the visual representation with instructions, retrieved evidence, and conversation state.

Documents & screenshots

OCR and native vision solve overlapping but different problems

NeedBest defaultWhy
Exact text extractionOCR / document parserDeterministic text coordinates and easier validation
Layout / chart / screenshot understandingNative vision modelCan reason over visual relationships rather than text alone
Text-rich PDFs with tablesOften bothParser for fidelity; VLM for interpretation
Handwritten / noisy visual textCompare bothAccuracy depends heavily on domain and image quality
Production pattern: extract deterministic structure first when possible; use the VLM where semantics or layout reasoning is required.
Speech & audio

Audio pipelines usually separate recognition from language reasoning

Waveform→Audio features→Speech model→Transcript / audio tokens→LLM

Classic modular design

ASR transcribes speech, then an LLM reasons over text. Easy to inspect and debug.

End-to-end multimodal design

The model may consume audio representations directly, preserving tone, timing, and non-verbal information that text transcription can discard.

Whisper mental model: audio is encoded, then a decoder predicts text tokens conditioned on those audio representations.
Temporal multimodality

Video = vision + time + brutal token budgets

Processing every frame at full fidelity is expensive. Practical systems sample frames, extract clips, compress temporal features, or retrieve only relevant moments.

60 sec × 30 fps = 1,800 frames

Frame sampling

Select periodic or scene-change frames. Cheap, but can miss brief events.

Clip encoding

Represent short temporal windows so motion and sequence are preserved.

Temporal retrieval

Index timestamps / scenes first, then send only relevant segments to an expensive model.

Engineering rule: video understanding is often a retrieval problem before it becomes a reasoning problem.
Multimodal RAG

Retrieve the modality that contains the evidence

Multimodal RAG can retrieve text, images, audio, or video segments and fuse them before generation.

Cross-modal retrieval

A text query can retrieve an image when both are embedded into compatible spaces.

Evidence fidelity

Do not convert everything to captions if the original visual contains details the caption may omit.

Inference engineering

Multimodal inputs change both context cost and latency

Preprocessing

Image resizing, tiling, audio feature extraction, and frame sampling add work before language generation starts.

Token pressure

High-resolution images or many video frames can consume large portions of the context budget.

Batching difficulty

Requests vary wildly in image dimensions, frame counts, and audio duration, making batching less uniform than text-only inference.

Measure separately: modality preprocessing time, encoder time, TTFT, decode latency, and total end-to-end latency.
Evaluation

Do not evaluate multimodal systems with text-only thinking

Failure typeExampleEval seam
PerceptionMisses the small warning iconVision / OCR benchmark
GroundingSees object but attributes wrong propertyRegion / evidence alignment
ReasoningReads chart correctly but computes wrong conclusionTask correctness
TemporalGets event order wrong in videoSequence / timestamp tests
Cross-modalTranscript conflicts with visual evidenceFusion consistency
Decompose failures. “VLM accuracy = 78%” tells you almost nothing about whether the encoder, OCR, temporal sampling, or reasoning layer failed.
What to remember

The multimodal 80/20

Raw modalities must first become vectors
CLIP-style training aligns text and image spaces
VLMs feed projected visual features into an LLM
OCR is for fidelity; native vision is for semantics/layout
Video requires temporal compression or retrieval
Cross-modal retrieval works through shared representations
More visual detail usually means more tokens and latency
Evaluate perception separately from reasoning

If you understand one sentence

Multimodal AI is representation alignment: encode each modality into useful features, align those features with the language model's representational space, then reason over the combined context.
