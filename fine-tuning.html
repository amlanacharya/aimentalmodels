Module 07 · Model adaptation

Fine-tuning, LoRA, PEFT & Alignment

The 20% that explains 80% of model adaptation: when to change prompts, when to retrieve knowledge, when to change weights, and how SFT, LoRA, QLoRA and preference optimization actually differ.

01 · Choose the right lever

Do not fine-tune until you know what is broken.

Prompting changes instructions. RAG changes available knowledge. Fine-tuning changes model behavior by updating weights. These solve different problems.

ProblemFirst leverWhy
Wrong tone / output formatPrompt / few-shotThe model likely knows the task already.
Needs fresh company knowledgeRAG / toolsDo not bake volatile facts into weights.
Repeated domain behavior is weakSFT / LoRAYou want a persistent behavioral adaptation.
Need a cheap adapter per taskLoRA / PEFTTrain a small parameter delta, not the whole model.
Need preference shapingDPO / RLHF-style methodsOptimize preferred behavior rather than only imitation.
Can prompting solve it?→ no →Missing knowledge?→ yes →RAG→ otherwise →Fine-tune behavior
Mental model: use the cheapest intervention that changes the failure mode you actually have.
02 · Supervised fine-tuning

SFT teaches by imitation.

You provide examples of the behavior you want. The model is trained to make those target responses more likely.

Training pair

Input: “Summarize this support case”
Target: concise structured summary

The model sees many examples of desired input → output behavior.

What changes

base model+demonstrations→updated weights

SFT is best understood as making a behavior habitual.

Use SFT for: stable style, task format, domain behavior, tool-call conventions, extraction patterns, and repeated task structure—not for frequently changing facts.
03 · Full fine-tuning

Full fine-tuning updates the entire model.

Maximum flexibility

Every trainable parameter can move. That gives high adaptation capacity.

Maximum cost

Optimizer states, gradients and trainable weights create a large memory footprint. Each tuned model also becomes a large artifact to store and serve.

04 · Low-rank adaptation

LoRA learns a small weight update instead of rewriting the whole model.

Freeze the pretrained matrix W. Learn two much smaller matrices whose product approximates the useful update.

W′ = W + ΔW
ΔW ≈ B · A
rank r ≪ model dimension

Base weights stay frozen

The expensive pretrained model remains unchanged.

Adapter stays small

You train and store the low-rank matrices, which can be attached to the same base model for different tasks.

Lowadapter capacity
~0.4%illustrative trainable share
smalladapter footprint

Illustrative intuition only: actual trainable percentage depends on architecture and target modules.

Rank intuition: higher rank gives the adapter more capacity but increases trainable parameters and memory. Higher is not automatically better.
05 · Quantized base + LoRA

QLoRA saves memory by quantizing the frozen base model.

4-bit frozen base+LoRA adapters→train adapters

What is quantized?

The pretrained base weights are stored in a low-bit representation to reduce memory.

What is trained?

The low-rank adapter parameters remain trainable while gradients flow through the frozen quantized base.

Why it matters: QLoRA made high-quality adaptation of much larger models possible on far less hardware than full fine-tuning.
06 · Parameter-efficient fine-tuning

LoRA is one PEFT method, not the definition of PEFT.

PEFT is the broader idea: adapt a pretrained model while training only a small subset or small added set of parameters.

LoRA

Add low-rank parameter updates to selected layers.

Prompt / prefix tuning

Learn trainable virtual prompt representations rather than changing all model weights.

Selective tuning

Train only specific layers, tokens or parameter subsets.

Engineering value: PEFT reduces training cost and makes multiple task-specific adapters easier to store and swap.
07 · Preference optimization

SFT says “copy this.” Preference training says “prefer this over that.”

Classic RLHF-style pipeline

preference data→reward model→RL policy update

Human preferences are modeled, then the policy is optimized against that learned reward while controlling drift.

DPO

chosen responserejected response→direct objective

DPO removes the separate reward-model + RL loop and optimizes pairwise preferences directly.

Prompt → Response A preferred over Response B
Mental model: SFT teaches examples of desirable behavior. Preference optimization teaches relative desirability among competing outputs.
08 · Data dominates

A weak dataset can permanently teach the wrong behavior.

represent real production tasks
remove contradictory examples
preserve difficult edge cases
separate train / dev / holdout
check label and response quality
avoid benchmark leakage

Quality beats blind volume.

Fine-tuning amplifies patterns in the dataset. More data only helps when it adds useful signal rather than inconsistency.

09 · Adaptation has side effects

Improving one behavior can damage another.

Catastrophic forgetting is the broad idea that adapting a model can degrade capabilities learned previously.

Before tuning

General model: broad capability, weaker domain behavior.

After aggressive tuning

Domain behavior may improve while generality, calibration or robustness can decline.

Practical defense: conservative training, high-quality data, PEFT where appropriate, and broad regression evals.
10 · Prove the tuning was worth it

Evaluate behavior, not training loss.

A lower loss only proves the model fit the training objective better. It does not prove the production system improved.
